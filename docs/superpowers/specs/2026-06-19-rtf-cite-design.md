# rtf-cite — RTF Citation Formatter (Design)

Date: 2026-06-19

## Purpose

A command-line tool that takes an RTF document containing auto-generated
plain-text citation markers, a BibTeX file, and a citation style, and produces
a new RTF document in which every marker is replaced by a properly formatted
in-text citation and a formatted bibliography is appended at the end.

The in-text markers are generated by an upstream tool and **cannot be changed**.
Their format (verified against the real `master_thesis.rtf`) is an
RTF escaped-brace group:

```
\{Author et al., "Title", Year\}
\{Author A et al., "Title A", YearA; Author B, "Title B", YearB; ...\}
```

- Braces are RTF-escaped (`\{` … `\}`); the enclosed text is plain.
- Multiple references within one marker are separated by `;`.
- Each reference is `Author phrase, "Quoted Title", Year`.

## Scope

In scope:
- Parse markers from RTF, match each reference to a BibTeX entry, render
  in-text citations and a bibliography per a chosen CSL style, splice results
  back into the original RTF, write to a new file.

Out of scope (YAGNI):
- Editing markers in place / round-tripping arbitrary RTF through pandoc.
- Generating markers from scratch.
- GUI.

## Engine Decision

**Pandoc as a citation renderer** (pandoc 3.9 already installed; built-in
citeproc is the reference CSL implementation, reads `.bib` directly, outputs
RTF). Pandoc does **not** parse the user's RTF (it cannot read RTF as input).
Instead the tool generates a small Markdown document containing only the
citation groups and a bibliography section, runs pandoc to get RTF fragments,
and splices those fragments into the original RTF itself.

Rejected alternatives:
- `citeproc-py` (pure Python): requires a hand-written RTF formatter and is
  unreliable on complex/note styles. More code, less correct.
- Full pandoc round-trip of the document: pandoc cannot read RTF as input.

## CLI

```
rtf-cite INPUT.rtf --bib export.bib --style nature [-o OUTPUT.rtf]
```

- `INPUT.rtf` — source document (positional).
- `--bib PATH` — BibTeX file.
- `--style NAME|PATH` — bundled style name (looked up in `styles/`) or a `.csl`
  path. Default: `nature`.
- `-o, --output PATH` — output file. Default: `<input-stem>_cited.rtf`. Never
  overwrites the source.

## Project Layout

```
rtf_cite.py            # CLI + pipeline (single small module, or a small package)
styles/                # bundled CSL files (self-contained), incl. nature.csl
tests/                 # pytest tests
tests/fixtures/        # master_thesis.rtf, export.bib
environment.yml        # conda env `rtf-cite`
README.md
```

The project is **self-contained**: CSL styles are copied into `styles/` rather
than read from Zotero at runtime.

## Pipeline

Each stage is an independently testable function.

1. **Extract markers.** Regex over the raw RTF bytes/text for `\{ … \}` groups
   that contain a `"quoted title"` and a 4-digit year (this distinguishes
   citation markers from other RTF groups such as `\{` literal braces or RTF
   metadata groups). Record each marker's exact source span. Split each marker
   on `;` into references; parse each reference into `(author_phrase, title,
   year)`.

2. **Index BibTeX.** Parse `export.bib` with `bibtexparser`. Build a lookup
   from normalized title (and author-surname + year as a secondary key) to the
   BibTeX cite key.

3. **Match.** For each reference, normalize its title (lowercase; strip RTF
   escapes, punctuation, and collapse whitespace) and look it up. On a title
   tie, disambiguate by first-author surname + year. Verified: 0 unmatched on
   the current `master_thesis.rtf` + `export.bib`.

4. **Render via pandoc.** Build a Markdown document. All references in **one**
   marker go into a **single** citation group so the style collapses them into
   one grouped citation — e.g. superscript `1,2,3` (not separate `1` `2` `3`)
   or `[1,2,3]` (not `[1][2][3]`). Concretely:
   - one line per marker: `«SENTINEL_n» [@key1; @key2; ...]`
   - a trailing `# References` heading.
   Run `pandoc --citeproc --csl styles/<style>.csl --bibliography <bib>
   -f markdown -t rtf`. Split the RTF output on the rendered sentinels to
   recover each marker's formatted in-text citation; capture the bibliography
   block following the References heading.

5. **Sanitize fragments.** Keep only a whitelist of inline RTF control words
   (`\i \i0 \b \b0 \super \nosupersub \uN…`, escaped specials, and plain text).
   Strip pandoc's document wrapper and any font/color-table indices so they
   cannot corrupt the user's Word-generated RTF.

6. **Splice.** Replace each original `\{…\}` marker span in the source RTF with
   its sanitized in-text citation fragment. Append the sanitized bibliography
   under a **"Bibliography"** heading inserted before the document's final `}`.
   (The `# References` heading in step 4 is only an internal pandoc sentinel.)
   Write to the output path.

## Error Handling

- **Unmatched marker** → warning to stderr listing each unresolved reference;
  the original `\{…\}` text is left intact in the output; the document is still
  produced. (Nothing is silently lost.)
- **Unknown style name** → print the list of bundled styles and exit non-zero.
- **pandoc not found** → clear error with an install hint.
- **Malformed bib / unreadable input** → clear error, non-zero exit.

## Environment

Conda env `rtf-cite` (Python 3.12) with `bibtexparser` and `pytest`. Pandoc is
an external system dependency (already installed). `environment.yml` captures
this.

## Testing (TDD)

- **Unit:** marker extraction (single + multi-reference, with `;`), reference
  parsing, title normalization + matching (incl. tie-break), fragment
  sanitization (whitelist enforcement), bib indexing.
- **End-to-end:** run the tool on the real `tests/fixtures/master_thesis.rtf`
  with `export.bib` and `nature` style; assert (a) zero unmatched, (b) known
  in-text citation strings appear, (c) a bibliography section is present, and
  (d) output is valid RTF (balanced braces, starts `{\rtf`).

## Success Criteria

- Running the tool on the sample thesis produces a `_cited.rtf` that opens in a
  word processor with Nature-style in-text citations in place of every marker
  and a Nature-style reference list under a "Bibliography" heading at the end.
- No source marker is silently dropped; unmatched ones are reported.
- A marker with multiple references renders as one grouped citation
  (e.g. `1,2,3` / `[1,2,3]`), not as separate adjacent citations.
